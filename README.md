# InspectFlow

InspectFlow is a demo AI visual inspection dashboard for a small manufacturing
team. It shows the full, auditable workflow a review team would use around a
defect classifier: upload a batch of images, review model predictions,
correct labels with a recorded audit trail, compare two model versions on a
shared evaluation set, and record a documented release decision.

**This is a portfolio/demo project.** All images, labels, and model
predictions are synthetic and generated by a deterministic demo classifier
(`inspection/demo_classifier.py`). No real manufacturing data, real trained
model, or third-party proprietary assets are used anywhere in this project.
Numbers shown in the app (accuracy, precision, recall, confidence) describe
the synthetic demo data only and must never be read as real-world
inspection performance.

## Workflow

1. **Batch upload** — upload a set of JPG/PNG images. Files are validated
   (type, size, count) and immediately run through the demo classifier,
   which stores a prediction, confidence score, and model version per image.
2. **Review queue** — filter/sort images by batch, predicted class, model
   version, and review status, with uncertain predictions surfaced first.
   Opening an image lets a reviewer assign or correct the ground-truth label
   and add a note; every correction is recorded in an audit trail with
   reviewer identity and timestamp.
3. **Model comparison** — pick two model versions and one evaluation set to
   get a confusion matrix, per-class precision/recall, and overall accuracy
   computed from the same labeled images for both models, plus a list of
   images where the two models disagree. Missing labels or missing
   predictions are reported explicitly rather than silently dropped.
4. **Release decision** — a release-candidate page summarizes metrics,
   comparison to the current baseline, review coverage, and known
   limitations, and lets a user record an approve / reject / needs-more-review
   decision with a rationale. Decisions are logged, not automated.

## Data model

`inspection/models.py` defines: `Batch`, `ProductImage`, `ModelVersion`,
`Prediction`, `Review`, `ReviewAudit`, `EvaluationSet`, and
`ReleaseDecision`. The demo inference logic (`demo_classifier.py`) and the
metrics/comparison logic (`evaluation.py`) are kept separate from the
review/release views, so a real trained classifier could later replace
`demo_classifier.classify()` without touching review, evaluation, or
release code.

## Demo classifier & dataset

- **Classifier**: `inspection/demo_classifier.py` hashes each image's base
  filename (directory ignored) together with a per-model-version salt to deterministically
  produce a predicted class and confidence score. It is *not* a trained
  computer-vision model. Two demo versions (`v1-baseline`, `v2-improved`)
  use different noise levels so their predictions plausibly diverge, which
  is what the comparison view is built to show.
- **Dataset**: seeded images are generated in-process with Pillow
  (`inspection/management/commands/seed_demo.py`) as simple synthetic
  colored panels with a drawn defect marker. No external image dataset or
  third-party licensed material is used.

## Setup

```bash
python -m venv venv
source venv/Scripts/activate   # Windows Git Bash / WSL; use venv\Scripts\activate on cmd
pip install -r requirements.txt

python manage.py migrate
python manage.py seed_demo      # add --reset to wipe and reseed to a clean state
python manage.py runserver
```

Then open http://127.0.0.1:8000/ and log in with the seeded demo account:

- username: `reviewer`
- password: `inspectflow-demo`

## Tests

```bash
python manage.py test inspection
```

Covers (22 tests): deterministic demo classification and stored-path handling, batch upload validation and
inference, review correction + audit trail, evaluation metrics (accuracy,
exclusion of unlabeled/missing-prediction images), model comparison
disagreements, and release decision recording.

## Known limitations of this demo

- Predictions come from a hash-based synthetic classifier, not a trained
  vision model — do not treat any accuracy/precision/recall figure shown as
  a real-world claim.
- Images are generated shapes, not real product photos.
- Authentication is a single shared demo reviewer account; a production
  deployment would need per-user accounts, roles, and stronger permissions.
- The review queue shows one prediction per image (the selected model's when filtering by model).
- Bootstrap CSS/JS load from a CDN, so the styled interface needs an internet connection.
- No background task queue — inference runs synchronously on upload, which
  is fine for demo-sized batches but wouldn't scale to large batches or slow
  models.
