# InspectFlow demo walkthrough

## The problem

A small manufacturing team wants to use an image classifier for defect checks but
cannot trust its output blindly. They need to see which predictions are
uncertain, have a person correct labels with a record of who changed what, check
whether a new model version beats the current one on the *same* reviewed images,
and record a documented release decision. InspectFlow demonstrates that
workflow end to end.

## Everything here is synthetic

- The images are generated by the seed command with Pillow (coloured panels
  with a drawn scratch, dent, crack or discoloration marker). No real product
  photos or third-party data are used.
- The "classifier" is a deterministic hash-based stand-in
  (`inspection/demo_classifier.py`), not a trained vision model. The two versions
  (v1 baseline, v2 candidate) differ only in a simulated noise level.
- Every accuracy, precision, recall and confidence value comes from that stand-in
  and the synthetic set. With a fresh seed the shared 30-image evaluation set
  gives about **0.767 (v1)** and **0.933 (v2)**. These figures show the workflow
  and say nothing about real inspection performance. The app labels them
  "synthetic demo data".

## Run it

```bash
python -m venv venv
source venv/Scripts/activate        # Windows Git Bash; on cmd: venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo --reset  # safe to repeat; restores the clean starting state
python manage.py runserver          # http://127.0.0.1:8000/
```

Login: `reviewer` / `inspectflow-demo`. Run `python manage.py seed_demo --reset`
again before each recording take to wipe uploads, corrections and decisions.

## What is implemented

- Batch upload with type, size and count validation, a progress bar, and
  synchronous demo inference storing class, confidence, model version and status.
- Review queue with filters (batch, class, model version, review status), sorting
  with the most uncertain predictions first, table on desktop and cards on phones.
- Image review: assign or correct the ground-truth label, add a note, and keep an
  audit history (reviewer, timestamp, old and new value).
- Model comparison on one shared evaluation set: accuracy, per-class precision,
  recall and support, confusion matrices, disagreement list with image links, and
  explicit warnings for unlabeled images or missing predictions.
- Release candidate page with metrics against the baseline, review coverage,
  known limitations, supporting examples, and a recorded approve / reject /
  needs-more-review decision with rationale and timestamp.
- Login required everywhere; uploaded images are served only to logged-in users.

Not implemented: production deployment, a real model, per-user roles beyond
login, background job processing, or any validation against real data.

## 60-90 second recording script

Use a desktop-width browser. Reset the seed first.

1. **Dashboard (0:00-0:10).** "InspectFlow is a demo of a defect-review workflow.
   Everything here is synthetic, which the banner and footer say." Point at the
   pending-review count.
2. **Upload (0:10-0:25).** Upload Batch, name it, pick 3 images, submit. Show the
   progress bar and the batch page with a prediction and confidence per image.
3. **Review (0:25-0:45).** Review Queue, most uncertain first. Open one, correct the
   label, add a note, save. Say: "the change is recorded with who and when."
4. **Correction moves the numbers (0:45-1:10).** Model Comparison: pick v1, v2 and
   the evaluation set, and Compare. Note the accuracies (0.767 and 0.933) and the
   confusion matrices. Open a disagreement row, change its reviewed label to
   the other model's prediction, save, and compare again: the accuracies shift
   (for example 0.733 and 0.967). Say: "both models are always scored on the
   same reviewed images."
5. **Release decision (1:10-1:30).** Release Decisions, open the v2 candidate.
   Show coverage, limitations and supporting examples, then record "Needs more
   review" with a short rationale. Say: "the tool provides evidence; a person
   makes the call."
